# 01_overview: 防災マップシステム概要

## 1. システム名称

- 仮称: **防災マップシステム（SVGMap Native + Next.js）**

## 2. 目的

- 防災関連情報および現場の活動状況を、地図上で直感的に可視化する Web 防災マップを提供する。
- 静的な地図ではなく、データ更新に応じて表示が切り替わる動的マップを目指す。
- 本システムは、以下の3つの主要業務レイヤーを中心に構成する。
  - **L1: ベースエリア**
    - 自治体境界、地区境界、区域情報などの基礎面情報
  - **L2: 避難所**
    - 指定避難所の位置に加え、施設名、住所、収容人数、施設種別、開設状況などの属性情報を保持するポイント情報
  - **L3: チーム活動**
    - 支援チームの現在地、活動地点、活動状況などの動的ポイント情報
- 洪水、土砂災害、気象、避難経路などは、必要時に重ねる**補助レイヤー**として扱う。
- SVGMap のハイパーレイヤリングを活かしつつ、CSV / Excel 取込、管理画面連携、リアルタイム更新へ拡張しやすい構成とする。
- 地図描画基盤は段階的に `SVGMap` へ一本化し、防災 UI と意味表現を優先した構成とする。

## 3. 対象ユーザ

- 地域住民
  - 自宅・職場周辺の危険度や最寄り避難所の位置を知りたい人
- 大学・研究機関の関係者
  - 対象地域の防災情報を可視化・分析したい人
- 自治体職員・防災担当者
  - 避難計画の検討、防災啓発資料の作成、訓練時の説明資料として利用する人
- 現場支援チーム・関係者
  - 活動地点や支援状況を把握・共有したい人

## 4. 利用シナリオ（例）

### 4.1 一般住民

1. トップページから防災マップを開く。
2. 地図上で自宅付近の地区を確認し、L1 ベースエリアから自分の位置関係を把握する。
3. L2 避難所レイヤを ON にして、最寄りの避難所を確認する。
4. 必要に応じて洪水・土砂災害などの補助レイヤを ON にして、周辺の危険度を確認する。
5. 緊急時には、利用可能な避難所や支援チームの活動状況を確認する。

### 4.2 自治体職員・防災担当者

1. 管理画面にログインする。
2. 避難所一覧 CSV / Excel をアップロードし、位置と属性をプレビューする。
3. チーム活動 CSV / Excel をアップロードし、地図上で位置・状態を確認する。
4. 問題がなければ公開し、本番マップへ反映する。
5. 必要に応じてハザードや気象レイヤを追加表示し、説明資料や訓練資料として利用する。

### 4.3 研究用途

1. 研究室で収集したセンサ位置、観測拠点、活動拠点などを追加レイヤとして投入する。
2. L1 / L2 / L3 と補助レイヤを重ね、地域防災上の分析や検討を行う。
3. 研究成果を画面キャプチャや印刷により資料化する。

## 5. スコープ

### 5.1 本バージョンで対応する範囲（MVP）

- 対象地域:
  - 既定 region は岡山
  - `regions/<regionId>/manifest.json` により追加 region を段階導入できる
- SVGMap による防災マップ表示
- 以下の主要レイヤ表示
  - **L1 ベースエリア**（自治体境界、地区境界、区域情報）
  - **L2 避難所**（ポイント）
  - **L3 チーム活動**（ポイント）
- 主要レイヤの ON / OFF 切替
- 選択地物の詳細表示
- `?region=` による region 切替
- CSV / Excel を入力元とした L2 / L3 データ取込
- 管理画面からの L2 / L3 データ更新（region ごとに段階的対応）
- 洪水・土砂災害など補助レイヤの重ね合わせ表示（任意）

### 5.2 将来拡張（この仕様書では設計のみ）

- 気象庁・国交省等のデータを利用した気象レーダー・河川水位との連携
- 岡山県内の主要河川ライブカメラとの連携
- 危険区域を考慮した避難経路表示
- PWA化・通知機能
- L3 のリアルタイム更新
- 市区町村詳細の背景補助表現

## 5.3 階層表示方針

- 本システムは、全国規模への拡張可能性を考慮し、地図表示を以下の3階層に分ける。
  - 全国 overview
  - 都道府県 overview
  - 市区町村詳細
- 全国 overview では都道府県の簡略化ポリゴンを表示し、L3 チーム活動の有無または件数を色分けで表す。
- 都道府県 overview では市区町村の簡略化ポリゴンを表示し、L3 チーム活動の有無または件数を色分けで表す。
- 市区町村詳細では region ごとの詳細 SVG を表示し、L1 / L2 / L3 の個別表示と詳細確認を可能にする。
- basemap は市区町村詳細でのみ表示し、全国 overview と都道府県 overview では表示しない。

## 6. システム構成概要
## 6.1 オンライン / オフライン対応

- オンライン時は対象 region の最新データ取得を試みる。
- 取得成功時は表示データと端末内キャッシュを更新する。
- 取得失敗時は端末内キャッシュを利用する。
- キャッシュも存在しない場合は `regions/<regionId>/...` 配下の fallback データを利用する。
- オフライン時はキャッシュ優先で表示し、利用者へ表示元と最終更新時刻を明示する。

- フロントエンド
  - Next.js（TypeScript 想定）
  - `/map` ページに SVGMap runtime を埋め込み
- 地図エンジン
  - SVGMap.js
  - Containers.svg / overview SVG / detail SVG / WebApp Layer
- データ
- L1 ベースエリア: region manifest が指す軽量化済み SVG / 地区辞書
  - L2 避難所: CSV / Excel を入力元として正規化した JSON。位置情報に加え、施設属性・収容人数・開設状況などを保持する
  - L3 チーム活動: CSV / Excel を入力元として正規化した JSON
  - 補助レイヤ: 洪水、土砂災害、気象、避難経路など
- データ取込
  - CSV / Excel をテンプレートに従って受け取り、変換スクリプトにより正規化 JSON を生成する
- region 構成
  - `regions/index.json`
  - `regions/<regionId>/manifest.json`
  - `regions/<regionId>/runtime-config.json`
  - `regions/<regionId>/district-dict.json`
  - `regions/<regionId>/municipalities.geojson`
  - `regions/<regionId>/shelters-fallback.geojson`
  - `regions/<regionId>/team-activity-fallback.json`
- 座標スキーマ
  - 各 region の共通座標系に基づき、L1 と補助レイヤの位置整合を行う
- L1 ベースエリアは、全国規模への拡張可能性を考慮し、面ポリゴンを表示の土台として扱う。
- L1 の選択操作は、初期実装ではポリゴン全面タップを前提とせず、地区ごとに配置した代表点または地区名ラベルを選択UIとして用いる。
- 代表点またはラベルを選択した場合、対応する行政区画・地区を強調表示し、詳細情報パネルに内容を表示する。

## 7. 非機能要件（概要）

- 対応ブラウザ: 最新の Chrome / Edge / Firefox / (スマホ) Chrome, Safari
- PC・スマホ対応のレスポンシブ Web デザイン
- 操作応答時間: ズーム・パン・レイヤ ON/OFF などの基本操作で体感 0.5 秒以内を目標
- L1 は軽量化済み SVG 資産を用い、モバイルでも極端に重くならない構成とする
- 管理画面は認証必須（現行は HTTP-only cookie session）
- L1 ベースエリアの選択操作は、初期実装ではポリゴン全面タップを前提としない。
- L1 の面は表示の土台として扱い、地区ごとに配置した代表点または地区名ラベルを選択UIとして用いる。
- 代表点またはラベルを選択した場合、対応する行政区画・地区を強調表示し、詳細情報パネルに内容を表示する。

## 8. 現時点の改善優先事項

本仕様の現時点での改善優先度は、次の順で扱う。

1. **L1 の選択方式の固定**
   - L1 は「面を表示し、選択は代表点またはラベルで受ける」を SVGMap runtime の正本仕様として固定する。
2. **仕様書の current path 追従**
   - 実装が先行しているため、仕様書側を current path に追従させることを優先する。
3. **管理認証の本番対応**
   - 管理画面は validate / preview / publish まで成立しているため、次は認証を本番寄りに置き換える。
4. **legacy 資産の方針決定**
   - current / legacy 分離後に、legacy を削除するか凍結するかを決める。
5. **SVGMap ネイティブ移行**
   - overview から詳細までを SVG 資産切替で構成し、MapLibre 依存を段階的に外す。

補足:

- L2 は region ごとの正本データソースの固定が必要である。
- L3 は更新主体と更新頻度を仕様で定義する必要がある。
- 検索は現在の実装で十分だが、将来の全国展開を考慮しサーバ検索への移行余地を残す。
